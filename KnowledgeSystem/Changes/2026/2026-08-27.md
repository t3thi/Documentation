# Semantic refinements from the Current State review on 2026-08-27

## CHG-2026-08-27-01

target: K-000004
operation: refine

### Before

Numeric Site Language IDs were documented as local configuration. Neither a
number nor a coincidentally matching locale was considered a reliable global
identity contract, but the role of backend UI safeguards and the limitation of
locale scope were not explicit.

### After

Backend UI safeguards improve consistent numeric-ID assignment but direct YAML
editing can bypass them. A locale alone is also too narrow for wider editorial
variants such as Easy Language.

### Evidence

- `review:current-state-2026-08-27`

### Reason

The refinement separates helpful UI behavior from the technical configuration
contract and explains why neither number-only nor locale-only identity is
sufficient.

## CHG-2026-08-27-02

target: K-000012
operation: refine

### Before

Complete per-language layers were disfavored partly because they could amplify
records, synchronization, Workspace versions, references and backend density.

### After

Record growth alone is not decisive. Complete layers remain disfavored where
universal shadows increase total synchronization, lifecycle, Workspace,
reference and backend complexity without a demonstrated net simplification.

### Evidence

- `review:current-state-2026-08-27`

### Reason

The current position prioritizes simpler processing logic over minimizing
database size while retaining the need for comparative measurement.

## CHG-2026-08-27-03

target: K-000021
operation: refine

### Before

The acceptable balance between persisted data and runtime complexity was
presented as directionally open alongside wider compatibility and ownership
decisions.

### After

The current direction favors explicit synchronized data and simpler code paths
over minimizing record count. Exact representation, lifecycle, migration,
compatibility, ownership and operational limits remain decision-required.

### Evidence

- `review:current-state-2026-08-27`

### Reason

The human review established a clear initiative preference without promoting
it into an adopted TYPO3 Core architecture.
