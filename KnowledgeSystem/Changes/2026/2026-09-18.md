# Semantic changes from the reviewed meeting on 2026-09-18

## CHG-2026-09-18-01

target: K-000029
operation: refine

### Before

The Knowledge base required every `-1` occurrence to be classified before
replacement, but had not yet classified the newly reviewed frontend and
persistence call paths.

### After

`ContentObjectRenderer`, the frontend `CategoryCollection` and Extbase's
`Typo3DbQueryParser` deliberately select records stored with Language All.
`LinkAnalyzer` uses a record's actual language and also has a separate `-1`
fallback whose future contract remains open.

### Reason

The meeting review and current Core code provide the call-path-specific
characterization required by the existing recommendation without changing its
overall migration direction.

## CHG-2026-09-18-02

target: K-000030
operation: create

### Before

The Knowledge base recorded the inline-child regressions but not the bounded
implementation proposed to address implicit child-language assignment.

### After

Gerrit 95476 derives a newly created inline or file-reference child's language
from its parent only when no explicit child language is supplied. Deliberate
language differences remain valid, and existing children are not changed.

### Evidence

- `transcript:2026-09-18`, patch status discussion before `16:34`
- `minutes:2026-09-18#topic-3-inline-child-language-patch-status`
- `gerrit:95476`, official status `NEW`, WIP, patch set 1, verified 2026-09-18

### Reason

The proposal is a durable, externally verifiable work item with a narrower
contract than changing every child's language with its parent. Its WIP and
human-review boundary remain explicit.
