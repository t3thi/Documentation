# Semantic changes from the reviewed meeting on 2026-09-04

## CHG-2026-09-04-01

target: K-000029
operation: create

### Before

The Knowledge base documented `-1` as a persisted Language-All value and its
planned replacement through explicit synchronization. It did not separately
govern synthetic `-1` values used as backend display, comparison or filter
selections.

### After

Synthetic backend selections should use explicit concrete language choices
instead of `-1` wherever their call paths permit it. During migration, `-1`
remains reserved for the value deliberately stored on a record as Language-All
synchronization intent. Every occurrence requires behavior-specific
verification before removal.

### Reason

The meeting distinguished persisted record semantics from synthetic UI state.
The subsequent Core inspection confirmed that both categories are active and
that their replacement must be reasoned about per call path rather than by
blindly replacing every literal `-1`.
