# Semantic changes from 2026-07-31

## CHG-2026-07-31-01

target: K-000022
operation: refine

### Before

The established selector requirement excluded parents already occupied in the
target language while retaining valid choices for the edited record.

### After

The requirement was generalized through each table's TCA
`transOrigPointerField`. Candidate and current-record type must match only when
the table's TCA `type` field uses `l10n_mode=exclude`. Other synchronized fields
and `allowLanguageSynchronization` are outside the rule.

### Evidence

- `transcript:2026-07-31`, public translation-parent selector discussion at
  `37:39-49:40`
- `minutes:2026-07-31#topic-2-translation-parent-selector-filtering`

### Reason

The meeting considered equality across every synchronized field, then used
`colPos` and unrelated excluded fields as counterexamples. The result was a
narrower type-field compatibility rule, not a contradiction.

## CHG-2026-07-31-02

target: K-000024
operation: supersede

### Before

Strict plus a configured fallback chain was treated as contradictory and
without an identified intentional product use case.

### After

The UK-to-general-English case established a valid regional reuse need. Strict
still means requested-language-only output; the valid need belongs in a more
expressive fallback policy without a forced terminal default language.

### Evidence

- `transcript:2026-06-11`, `00:16-20:23` and `25:09-29:40`
- `minutes:2026-06-11#topic-1-strict-mode-and-fallback-chain-regression`
- `transcript:2026-07-31`, `49:44-1:01:20`
- `minutes:2026-07-31#topic-3-strict-mode-and-non-default-fallback-chains`

### Reason

Later project context changed the interpretation of the configuration without
changing the strict-output contract.
