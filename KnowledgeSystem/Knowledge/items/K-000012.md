# Complete per-language layers are disfavored, not rejected

## Statement

One possible model materializes every structural position in every relevant
language and uses language-layer shadows where visible content is absent. The
initiative currently disfavors this direction relative to a shared layer, but
has not rejected or disproved it.

## Rationale

The model provides self-contained language structures and local ordering. A
higher record count is acceptable when explicit data materially simplifies
processing. Universal shadows may nevertheless add synchronization and
lifecycle work, Workspace versions, references and visible Layout density, so
the relevant question is whether the complete model reduces total complexity.

## Consequences

The option remains active for comparative prototyping. Record growth is not a
standalone rejection criterion; code and runtime simplification, lifecycle
costs, backend usability, performance and volume must be measured together.
