# Compatibility and ownership require wider decisions

## Statement

The initiative's current direction favors explicit persisted synchronization
data and simpler, more predictable code paths over minimizing record count.
The exact representation, lifecycle, measurable operational limits,
compatibility and deprecation, extension APIs, migration and responsible Core
and product owners remain open.

## Rationale

The current assessment is that processing complexity is the more important
systemic risk than database size alone. This supports materialized synchronized
records when they remove special-case runtime logic, but it does not select a
specific storage or Structural-Identity model. The initiative also does not
claim sole authority over TYPO3 strategy or Core architecture.

## Consequences

Proposals must demonstrate whether additional explicit records actually
simplify code and runtime behavior, identify decision authority and quantify
record volume, write amplification, queries, Reference Index, Workspaces and
backend usability where relevant. Record growth alone is not a rejection
criterion.
