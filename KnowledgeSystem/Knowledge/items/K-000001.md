# Four responsibilities must be separated

## Statement

The initiative separates four responsibilities: Language Identity,
Synchronization Intent, Structural Identity and Output Policy. This is a
problem decomposition and review order, not a selected database schema, API or
migration sequence.

## Rationale

Current values and relations combine several meanings. Separating the questions
keeps a solution for one concern from silently deciding another.

## Consequences

Proposals must state which responsibility they affect and must not present this
conceptual model as an adopted Core architecture.
