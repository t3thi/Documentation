# Translation-parent eligibility was refined on 2026-07-31

## Statement

The translation-parent selector should exclude candidates that already have an
active translation in the target language while retaining the record's current
parent. The rule applies via a table's TCA `transOrigPointerField`. If the table
defines a TCA `type` field and that field uses `l10n_mode=exclude`, candidate and
record type must match.

The equality requirement deliberately does not cover every excluded or
synchronized field. `colPos` can differ intentionally, unrelated excluded fields
are not structural prerequisites, and `allowLanguageSynchronization` remains
editor-controlled.

## Rationale

The July 24 duplicate-parent rule was generalized on July 31. A broader proposal
to compare synchronized fields was narrowed after concrete counterexamples.

## Consequences

The WIP Core implementation must stay generic across translatable tables while
avoiding an over-restrictive selector. The requirement is supported but not yet
implemented in Core.
