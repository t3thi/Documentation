# Strict output must remain distinct from fallback

## Statement

`fallbackType: strict` must render only records from the requested language.
`fallbackType: fallback` may render another language along an explicit chain.
A stored chain must not silently alter strict semantics.

## Rationale

The modes make different promises to editors. A merged fallback correction
exposed a regression in which hidden requested-language content could fall back
under `strict`.

## Consequences

The strict regression needs a bounded Core fix. A regional UK-to-English use
case should be expressed by fallback policy without forcing an unwanted
terminal default-language step.

This requirement is not the current implementation contract. Baseline Core
can consult configured fallback IDs under `fallbackType: strict`.
Gerrit 94510 stops fallback when a translated candidate is hidden under
`OVERLAYS_ON` or `OVERLAYS_ON_WITH_FLOATING`, but a missing translation can
still fall back. It therefore does not implement the complete single-language
requirement. Content behavior under `fallbackType: free` must not be generalized
to page resolution. The reviewed meeting leaves release/backport policy open.

On 2026-10-30, patch set 11 remains unmerged and mergeable, with André's
`Verified +1` and `Code-Review -1`, Benni's positive review and one unresolved
comment. Functional verification of the bounded fix is not semantic agreement
to merge it. No definitive introducing commit is established by this meeting.
