# Editing Language is a preferred product concept

## Statement

The preferred product concept lets an editor choose the content language from
which they work, independently of backend interface language. A Chinese editor,
for example, could create Chinese content from English even when German is the
site default.

## Rationale

Permanently privileging the default-language column can make the source
incomprehensible and couples editing context to structural lead.

## Consequences

This is not implemented in Core. The demonstrator in `K-000034` now keeps an
Editing Language per site and applies it to Page Tree and Layout. The reviewed
2026-10-23 meeting asks that it remain visible in Language Comparison and be
excluded from the deselectable comparison-language set on that condition.
Comparison selection should survive view changes. Whether temporarily viewing
another Layout language should also replace the remembered working source is
still an editorial question; the prototype keeps the coupled behavior for now.
Configurable backend label fallback, translation actions, permissions,
ordering, migration and source-provenance behavior still need validation.
