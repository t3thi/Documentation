# Numeric language IDs are local configuration

## Statement

The same human language can receive different numeric IDs in separate sites,
while one numeric ID can be labelled as different languages across sites. The
backend UI guards against duplicate assignments and makes consistent reuse of
an ID easier, but direct editing of Site YAML can bypass those safeguards.

The number is therefore not a reliable global identity contract. A locale
alone is also insufficient: its conventional language-and-region scope does
not reliably represent wider editorial variants such as Easy Language.

## Rationale

The guarded backend workflow improves consistency but does not change the
technical configuration contract. Shared storage and cross-site record use
must remain correct when Site configuration was edited directly or when the
required semantic distinction exceeds a conventional locale.

## Consequences

Shared storage, metadata, import and export require an explicit semantic
identity mapping rather than assuming equal local numbers or locales mean
equal editorial language identities.
