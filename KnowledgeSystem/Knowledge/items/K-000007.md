# Replace Language All with explicit concrete synchronization

## Statement

The initiative's strong direction is to express "maintain once for several
languages" as record-wide synchronization intent applied to concrete language
variants, not as a fictitious `-1` language. The first stage should target all
defined languages and enforce every parity-relevant field without an ineffective
editor opt-out.

## Rationale

Concrete variants separate identity from behavior and may reuse existing target
creation and dependency propagation paths.

## Consequences

This remains an unvalidated approach, not an adopted API. It cannot be enabled
safely until target resolution, conflicts, provenance, atomicity, lifecycle,
Workspaces and migration are defined.
