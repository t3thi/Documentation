# Structural identity requires wider decisions

## Statement

The exact owner and representation of logical structure, per-language
placement and absence, visibility to APIs and editors, lifecycle and migration
remain undecided. Today the real language represented by
`sys_language_uid = 0` is also the structural parent and lead for connected
variants. Removing that special meaning from Language Identity therefore
requires an explicit model to assume structural reference and leadership
without privileging one real output language. Shared hidden structure,
complete language layers, sparse and bounded hybrid models require comparison
against the same acceptance cases.

## Rationale

A preferred hypothesis does not settle Core-wide data, permission, Workspace,
reference or compatibility contracts. In particular, the current preference
to investigate a shared hidden structure is a possible answer to the lost
Default-Language lead, not a selected prerequisite or implementation of a
BCP-47 migration.

## Consequences

Free, Connected and Mixed modes cannot safely disappear from normal editor UX,
and `0` cannot lose its structural special role, until the selected model
preserves current independent outcomes and supplies a credible migration. This
dependency does not select between the candidate structure models.
