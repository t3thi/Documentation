# Synchronization should include parent-owned child values, not shared targets

## Statement

When synchronization is selected or enforced for a composite parent field,
the intended scope includes the relevant values of its parent-owned one-to-many
IRRE children, recursively through nested owned children. For a file field,
that includes the owned `sys_file_reference` and its crop, not the shared
`sys_file`. Independently reusable records reached through MM relations are
outside that implied scope: synchronizing one parent must not silently
overwrite values used by other parents.

## Rationale

The reviewed meeting reports that initial localization copies a crop but
later changes do not propagate when the parent's image field is synchronized.
Forge 88024 documents the same expectation under `allowLanguageSynchronization`
and `l10n_mode=exclude`. This is a durable editorial requirement, not proof of
a newly introduced v13 regression or a reproduced project configuration.

Current Core configures file-reference relations, discovers synchronization
fields from each table's own TCA and reconciles relation membership/order.
It does not automatically derive synchronization for every existing child
value from the parent field. Standard `crop` TCA has access-control
`exclude: true`, not localization `l10n_mode=exclude` or
`allowLanguageSynchronization`. The merged child-language alignment in
`K-000037` is a different operation and does not implement this requirement.

## Consequences

No recursive synchronization API or migration has been selected. Ownership
must be resolved from the actual relation configuration, not the `inline`
type alone; MM targets are excluded and cascading deletion is separately
controlled by `behaviour.enableCascadingDelete`. Characterize nested relations,
local child overrides, Workspaces, permissions, cycles and lifecycle before
changing propagation. Globally enabling synchronization on every crop field
does not express the proposed parent-context-specific contract. Historical
workarounds and the reported failed recent attempt require installation-specific
verification; no v13 runtime test or complete arbitrary-depth audit was run.
