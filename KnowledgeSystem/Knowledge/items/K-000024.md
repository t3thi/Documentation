# The assumption that strict-plus-chain has no valid use was superseded

## Statement

In June the team could not identify an intentional reason to configure a chain
with `strict` and treated removing the chain as a plausible workaround. The
later UK-to-general-English case superseded that assumption: the configuration
was expressing a valid need to reuse English without an unwanted terminal
fallback to German.

## Rationale

The use case changed the understanding of why the configuration existed, not
the meaning of strict output.

## Consequences

Strict must still render only the requested language. The valid need belongs in
a more expressive fallback policy, potentially with an optional terminal
default step.
