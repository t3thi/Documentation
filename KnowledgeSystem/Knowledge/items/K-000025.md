# Runtime cleanup of inactive fallback chains was rejected

## Statement

The initiative rejected automatically deleting fallback-chain values when a
non-fallback mode is saved. It also rejected clearing them only at runtime,
because the backend editor would then load an empty value and a later save would
have the same destructive effect.

## Rationale

Projects may switch modes and TYPO3 normally tolerates inactive or unknown YAML
keys. Removing stored configuration is broader than fixing output behavior.

## Consequences

Stored YAML remains intact. Rendering should ignore the chain unless the active
type is `fallback`; hiding or explaining the field is a separate UI question.
