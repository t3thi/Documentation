Problem

The missing case sits in the middle

identicalreducedenrichedchangedindependent

Mostly connected, selectively different

Timing: 02:00 to 03:30.

TYPO3 handles identical translated structures and fully independent structures. The product gap appears when a language variant shares most of the structure but needs a small local addition or omission. Today that can require Mixed Mode, loss of the connection, or an artificial default language partner.

Sources: T3THI minutes, 26 June 2026, T3THI minutes, 10 July 2026.

Boundary: Free Mode remains a legitimate endpoint. Its deprecation is not established.

Problem

Three use cases reveal three different gaps

Local additionContent only in the target languageGap: Connected Mode requires a default partner
Global storageShared records across sitesGap: Numeric IDs have only site-local meaning
Regional fallbacken-GB may reuse en, not deGap: One chain cannot express per-position intent

Timing: 03:30 to 05:00.

The first gap is structural: Connected Mode expects a target-language record to have a default-language partner. The second is identity: numeric language IDs are configured per site, so shared storage cannot derive one global language identity from the number alone. The third is output policy: one configured fallback chain does not say whether a missing position should continue through fallback or remain intentionally absent.

Sources: T3THI minutes, 29 May 2026, global storage case, cross-site language case, current relation modes, current site language properties, current fallback mapping.

Boundary: Each case exposes a distinct gap. The examples do not imply one shared implementation defect.

Current · Interacting contracts

Four questions use different contracts

Language identitySite config maps IDs to languages0 default · −1 all
Synchronization intentWhich fields or records stay in sync?l10n_state · −1
Structural identityDo records belong together? If so, which ones?l10n_parent · mode
Output policyWhich records may render?fallbackType · fallbacks

Timing: 05:00 to 06:30.

Current Core does not answer these questions with one model. Site configuration maps numeric IDs to languages. Zero additionally denotes the default language and structural source. Minus one denotes one record for all languages. Localization state controls selected fields. Origin pointers and Page module modes describe record relations. Site fallback type and fallback IDs control frontend selection.

Sources: current site language configuration, current language values, current field states, current relation modes, current output mapping.

Boundary: The four-row mapping is an explanatory decomposition, not one existing Core API or one data model.

Vision · Problem decomposition

Separate four responsibilities

1Language identityWhich human language does this content represent?
2Synchronization intentWhich fields or records stay in sync, and where may they differ?
3Structural identityWhich records are the same logical node across languages?
4Output policyWhat should render when the requested variant is missing?

Make each contract explicit, then decide how the database represents it.

Timing: 06:30 to 09:00.

This is the organizing model for the rest of the talk. Identity names the human language. Synchronization intent states what remains aligned. Structural identity links logical nodes across variants. Output policy decides what a request may render. The following slides keep this order.

Sources: T3THI minutes, 8 May 2026, T3THI minutes, 11 June 2026, T3THI minutes, 26 June 2026.

Boundary: This is a design decomposition, not a selected data model.

Vision · 1 Language identity

Site language IDs have only local meaning

Site A · ID 9→en-GB←Site B · ID 14

Direction: BCP 47 provides shared language identity.

Timing: 09:00 to 10:45.

Each site language has a configured integer ID. The same human language can therefore use different IDs in different sites. Zero also denotes the default language and translation source. Minus one is a special record value for all languages, not a human language. BCP 47 is the preferred semantic identity across sites and shared storage. Record storage, migration and the future role of numeric keys remain open.

Sources: RFC 5646, TYPO3 Camp RheinRuhr 2024 presentation, T3THI minutes, 10 November 2023, T3THI minutes, 25 July 2025, current SiteLanguage properties, special record language values.

Boundary: BCP 47 is not current record storage in Core.

Open · 2 Synchronization intent

Synchronization needs rules for start, change and stop

Starthandle existing language versions
Changedefine allowed local differences
Stopkeep, detach or delete generated versions

A flag alone is not enough

Timing: 12:15 to 13:45.

Enabling synchronization must handle existing variants. Disabling it must decide whether generated variants are removed, detached or kept. New site languages, manual changes, workspaces, restore, delete and references all need explicit rules. A flag without this lifecycle would create another special case.

Sources: T3THI minutes, 31 January 2025, T3THI minutes, 29 May 2026, T3THI minutes, 24 July 2026.

Boundary: These questions are unresolved design requirements.

Vision · 3 Structural identity

Connected Mode needs local additions

Default languageA→B→C
Target languageA→B→C→Local

Need: add Local without a default-language placeholder

Timing: 13:45 to 15:30.

In current Connected Mode, translated records point to a default-language record. A target-language-only record has no such parent and is treated as standalone content, which can create Free or Mixed Mode semantics. The requirement is to keep A, B and C connected while adding Local only in the target language, without creating an unused default-language placeholder. Strongly divergent structures may still use Free Mode.

Sources: T3THI minutes, 26 June 2026, T3THI minutes, 29 May 2026, current Connected, Free and Mixed Mode detection.

Boundary: The structural partner mechanism is not selected or implemented.

Vision · 3 Structural identity

Editors choose the language they translate from

Site defaultGerman

Editing languageEnglish

Translate intoChinese

The editing view shows English instead of German as its source

Timing: 15:30 to 17:00.

Editing Language defines the content language from which an editor works. In this example, German remains the site default, but a Chinese editor chooses English as the source for Chinese translations. The Page module would show the English positions where it currently places the default language, so German text does not obstruct this workflow. Editing Language is separate from the backend user interface language.

Sources: T3THI minutes, 8 May 2026, T3THI minutes, 29 May 2026.

Boundary: Editing Language remains a product direction and prototype topic.

Open · 3 Structural identity

A complete layer gives every language the same record positions

Potentialmissing positions are explicitless runtime lookup
↔
Costmore recordsmore sync and workspace work

Direction: complete layers. Representation remains open.

Timing: 17:00 to 19:00.

Complete language layers can make absence explicit and reduce runtime overlay cases. Materializing structure also increases record count and raises provenance, workspace, reference, migration and performance questions. Shadow records, a hidden zero spine and a neutral structure layer are distinct models. None is selected.

Sources: TYPO3 Camp RheinRuhr 2024 presentation, T3THI minutes, 24 October 2025, T3THI minutes, 8 May 2026, T3THI minutes, 10 July 2026.

Boundary: Completing layers is a direction. The representation and cost model remain open.

Current · 4 Output policy

Backend connection is not frontend fallback

Backend
record→l10n_parent→relation
Frontend
request→fallback policy→output

Timing: 19:00 to 20:30.

The backend origin pointer describes an editorial and structural relation. Site fallback and LanguageAspect determine which records are rendered. Connected therefore does not answer what the frontend displays. Core keeps these mechanisms in separate code paths.

Sources: backend relation modes in Core, frontend fallback mapping in Core, T3THI minutes, 15 December 2023.

Boundary: The two lanes interact at runtime but remain different responsibilities.

Open · 4 Output policy

Absence must tell fallback whether to continue

Configured chainen-GB → en → de (default)
missing translationcontinue through allowed fallbacks
intentionally omittedstop and render nothing

Current fallback configuration has no per-position intent

Timing: 20:30 to 21:45.

In this example, language zero is the final configured fallback. A missing English variant should continue through the allowed chain. An intentionally omitted position should stop and render nothing. Current Core applies the configured language-wide chain but has no per-position intent for this distinction. Core does not automatically append language zero to every valid chain, so the problem applies where zero is configured. Strict behavior remains separate.

Sources: T3THI minutes, 11 June 2026, T3THI minutes, 10 July 2026, configured fallback language IDs, fallback order and overlay type.

Boundary: The per-position intent is a future requirement. Language zero is terminal only where it is configured.
