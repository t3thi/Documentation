## Topic 1: Human Review Explorer for Language-All Findings

Eric presented the completed discovery phase for Language-All handling in the TYPO3 Core. Direct searches for the literal `-1` and related markers were combined with inverse searches that traced the concept back to relevant code. The resulting 80 candidates had been analyzed independently by two models, Astra and Opus, without either model seeing the other's result. Their assessments were then consolidated as preparation for human review rather than treated as decisions.

The underlying findings were stored as JSONL data and exposed through a [Human Review Explorer](https://content.eric-harrer.de/t3thi/reviews/95619/). The explorer showed the affected expression, value origin, eventual consumer, model assessments, evidence, test evidence, earlier human review and the current human decision for each candidate. It also provided filters, German and English views, and links to individual cases. Eric emphasized that agreement between the models was only a signal and that the human gate remained authoritative.

The team compared the explorer's output with the previously reviewed `ContentObjectRenderer` cases. Both models had classified one occurrence as synthetic, while the initiative's earlier code-path review had established that the expression queries the configured language field of a language-aware record table and that `-1` represents stored Language-All records. This discrepancy reinforced the need to inspect the evidence and Core code instead of accepting model classifications automatically.

## Topic 2: Scope and Semantics of the Language-All Marker

The team continued reviewing [Gerrit change 95619](https://review.typo3.org/c/Packages/TYPO3.CMS/+/95619). André suggested also introducing a named marker for the Default Language value `0`, because expressions frequently contain both `0` and `-1`. Eric agreed with the general idea, but the team concluded that expanding the current analysis and patch to every use of `0` would make its scope too broad. A Default Language marker could instead be addressed in a follow-up change while the current patch remained focused on Language All.

Eric revisited the difference between `-1` stored in a record's language field and synthetic `-1` values used by backend selectors or filters. The patch description primarily explained the record-level meaning, although the proposed marker was also applied in synthetic contexts such as Recycler and backend display logic. For the current patch, the team agreed to use the same marker wherever the value means All Languages and not encode those semantic differences in separate constants yet. Any description of the marker should therefore avoid implying that it applies exclusively to database language fields. A later refinement may still separate the underlying contracts.

## Topic 3: Patch Coverage and Human Review Method

The team simplified the review method to avoid reconstructing every complete call path when the local meaning was already clear. Model agreement could identify likely candidates, but every occurrence added to the patch would still receive a human plausibility check against the actual code. A case would be accepted when `-1` clearly meant All Languages, investigated further when the meaning was unclear, and removed if it was an unrelated calculation or another false positive.

Eric and André then sampled the occurrences already changed by the patch across backend controllers and record lists, TCA form-data handling, `DataHandler`, `SlugHelper`, `PageRepository`, file metadata handling, site-language access and routing, and Extbase persistence. They found no false positive among the patch's current occurrences: every reviewed literal or marker represented All Languages, even when the value was synthetic rather than read from a record.

The explorer also contained relevant candidates outside the current patch, including surrounding unchanged code and findings discovered by inverse search. Eric agreed to finish reviewing those candidates, add all plausible missing occurrences to the patch, and add direct Core permalinks to the explorer to make later review easier. The team planned to recheck the expanded patch together by sampling the additions before removing the WIP state. Eric also agreed to post a concise Gerrit update explaining that the existing occurrences were valid, that further candidates had been found, and that the patch would be updated without distinguishing the different Language-All contexts in the marker for now.
